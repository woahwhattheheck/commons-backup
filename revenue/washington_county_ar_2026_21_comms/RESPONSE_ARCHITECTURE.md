# Response architecture for an evidenced prime

This is a response skeleton, not completed bid language. Every claim must be rebound to prime/partner evidence.

## 1. Executive fit
- identify bidding legal entity and named implementation lead;
- state exact proposed platform/brand names;
- state one-platform ownership and support boundary;
- disclose every subcontractor/partner and division of responsibility;
- make no TJLabs prime-experience claim.

## 2. Cross-channel service design
- one Agency-controlled knowledge base and versioning mechanism;
- phone/voice, AI chat, live chat, native email, SMS follow-up;
- one constituent/case identity across channel transitions;
- automatic case creation/transcription/summary for voice;
- queue-aware live-chat handoff and off-hours behavior;
- automatic language detection plus documented fallback.

## 3. Property-record / CAMA integration
- read-only architecture from incumbent interface discovered with Agency;
- modern API adapter if available; otherwise vendor-supported export, replica, secure file exchange, or another County-approved read-only pattern;
- data mapping for parcel, ownership, value, exemption, application, protest/appeal;
- identity policy for account-specific disclosures;
- source-record deep links for staff;
- retry/staleness/error handling and integration observability;
- explicit contractual ownership by prime and named subcontractor responsibility.

## 4. Security, privacy, and IT approval
- no Agency data path activated before written County IT approval;
- data-flow diagram, subprocessors, retention, encryption, access controls, model/data-training policy, incident path, logging, support-access controls;
- DNS plan for SPF/DKIM/DMARC;
- telephony/A2P registrations and ownership;
- accessibility evidence/VPAT.

## 5. Ten-business-day implementation
- Day 0 kickoff + incumbent-interface discovery;
- Days 1-2 source ingest / knowledge corpus and identity/integration boundary;
- Days 3-5 configure two agreed staff-review channels plus synthetic adapter;
- Days 6-8 run historical-inquiry validation and correction loop;
- Days 9-10 staff review build and acceptance evidence;
- no public launch until Agency validation sign-off.

This schedule is only usable if the proposed prime can actually commit resources and platform readiness; it is not a promise by this carrier.

## 6. Acceptance and historical replay - TJLabs seam
Use the synthetic harness as the seed for an Agency-approved test pack:
- same-case phone -> email -> chat continuity;
- knowledge version parity across channels;
- public vs account-specific field disclosure;
- identity-not-confirmed denial cases;
- legacy record missing/stale/duplicate/malformed cases;
- no write/mutation through property adapter;
- human handoff context preservation;
- deterministic regression receipt per candidate release.

## 7. Experience / reference matrix
For each of the five required projects: jurisdiction, dates, inquiry domain, channels, volumes if evidence-backed, system-of-record integration, incumbent product where permitted, contactable reference, artifact/reference URL. Never repurpose a subcontractor's work as prime work without clear attribution.

## 8. Commercial response
Populate every Section 12 line from authorized prime pricing only. State voice billing basis and concurrent-session cap. Include CAMA integration, 15 licenses, implementation/configuration/initial KB build/on-site email-go-live training, overage, added licenses, SMS, all-in year one, and optional multiyear pricing.

## 9. Submission preflight
- current Beacon packet/addenda fetched;
- packet digest/source ledger updated if changed;
- all addenda acknowledged;
- authorized signature;
- insurer letter and proof;
- Arkansas-required certification reviewed and authorized;
- exceptions isolated in a separate document;
- sample contract if applicable;
- no blank/negotiable/case-by-case price fields;
- final collision check and single submission owner.
