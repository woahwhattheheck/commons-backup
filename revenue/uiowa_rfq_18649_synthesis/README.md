# Evidence-preserving cross-group synthesis

UIOWA-028 / ZZ-F4BC7C35 / GPT-6 Astra Pro.
An offline, standard-library tool for turning annotated group findings into
reviewable themes without double-counting shared sources or hiding disagreement.
All committed examples are fictional. No University assessment has been performed
by running this tool.

## Run the complete example

From the repository root, with Python 3.10 or newer:

```sh
cd revenue/uiowa_rfq_18649_synthesis
python -m unittest -v test_synthesis.py
python -O -m unittest -v test_synthesis.py
python synthesis.py fixtures/synthetic.json > /tmp/uiowa-028-themes.json
python synthesis.py fixtures/synthetic.json --format markdown > /tmp/uiowa-028-themes.md
python synthesis.py fixtures/synthetic.json --format csv > /tmp/uiowa-028-themes.csv
```

The CLI reads one explicit JSON file and writes the selected representation to
standard output. It makes no network calls and does not mutate input files.
Malformed input exits 2 with a field-specific error on standard error.
Normal completion exits 0, including a report containing unresolved evidence.
Use a new output path: shell redirection, not this program, controls overwriting.

The fixture has 13 findings and 8 sources, producing 8 themes. In particular,
one shared recovery source reaches ESS/RIS/IAM but counts as one declared support
cluster; IAM's counterexample makes the theme contested. Two equally long delivery
waits remain separate because the supplied mechanisms differ.

## Files

- `synthesis.py`: validation, declared-correlation clustering, synthesis, JSON/CSV/Markdown CLI.
- `test_synthesis.py`: executable positive, contradiction, unknown, malformed-input and interchange cases.
- `fixtures/synthetic.json`: source excerpts and finding annotations; complete worked input.
- `examples/themes.md` and `examples/themes.csv`: outputs generated by the actual CLI.
- `28-synthesis-method.md`: reasoning rules, action-scope table, cases, and reviewer worksheet.

## Input contract

Root fields: `schema="uiowa-synthesis/v1"`, `dataset_id`, `data_status` (`synthetic`
or `engagement_evidence`), `sources`, `findings`. The latter label is supplied by
the operator and is not an authentication claim. Never commit private engagement
records to this public repository.

Source fields: unique `source_id`, `source_ref`, `locator`, `version`, `excerpt`,
`evidence_kind` (`artifact`, `metric`, `interview`, `policy`), nullable `origin_id`,
and optional nullable lowercase `content_sha256`. Digests are supplied identity
hints, not downloaded or authenticated by the tool. An origin describes a common
underlying event/collection; it is not simply an organization name.

Finding fields: unique `finding_id`, `group` (`ESS`, `RIS`, `IAM`), `dimension`
(`software`, `security`, `deployment`, `ai`), `practice_key`, `service_id`,
`statement`, `context`, ISO `window_start` / `window_end`, `state` (`strength`,
`gap`, `unknown`, `not_applicable`), `basis` (`observed`, `reported`, `unknown`),
`topology` (`local`, `shared`, `unknown`), nullable `dependency_id`, nullable
`mechanism_id`, `mechanism_basis` (`supported`, `hypothesis`, `unknown`), and the
source-ID arrays `support_ids`, `dissent_ids`, `limitation_ids`,
`mechanism_source_ids`. Unknown/non-applicable findings also require `rationale`.

Each shared finding needs a dependency ID. Local/unknown topology must use null
for that field. A supported mechanism needs source references. Unknown mechanisms
must have null IDs. A strength/gap needs support; policy/interview-only support
cannot be labeled observed. All source references must resolve inside the packet.
Additional fields are preserved in underlying JSON findings/sources but do not
change synthesis decisions. They do not become verified scores or authorities.

## Integration and output contract

`synthesize(packet)` returns `uiowa-synthesis-report/v1`. Each theme retains its
complete original findings, all supporting/dissenting/limiting/mechanism sources,
exact locators, related findings outside the theme, covered and uncovered groups,
source counts, declared correlation clusters, and a proposed action shape/role.
Theme IDs are deterministic from the comparison and mechanism grouping keys.
Input order does not change the resulting report.

The existing workshare's group, dimension, source-ID and source-ref vocabulary is
preserved. Its authority bundle is **not** this input schema: an analyst must add
explicit finding scope, evidence-role, dependence, and mechanism annotations.
Do not infer those fields from maturity/confidence values or automatically copy
compiler authority into this packet. No direct compiler adapter is claimed.

The JSON report is the full-fidelity interchange. CSV is an exportable theme table,
not a lossless source register. Markdown is a readable table plus supporting and
dissenting excerpts. Compare generated example bytes to detect output drift.

## Interpretation limits

This is a structural synthesis assistant, not a fact verifier, causal model,
statistical estimator, maturity calculator or approval service. Different source
clusters are not necessarily independent. `sample_supported` describes internally
sufficient supplied annotations, not authenticated findings. A missing group is
not a gap. `sampled_all_three_groups` never establishes department-wide prevalence.
The proposed owner is a role, not a staffing assignment or appointment.
