# Paid Sunflower migration / federal-asset acceptance workshare

**Status:** `PROPOSED_NOT_ACCEPTED`
**Reference carrier:** `woahwhattheheck/commons#14892`
**Commercial hypothesis:** **$28,000 fixed** base sprint + **$9,500 fixed** optional cutover dress rehearsal.

This is a subcontract/workshare concept for a qualified government-property platform vendor or systems-integration prime. It is not a direct response to GTRI IFB 2027-IFB-GTRI-0006 and does not represent TJLabs as the platform publisher, federal-property authority, security assessor, auditor, or buyer-compliance certifier.

## Outcome

Provide an independent, evidence-bound answer to one narrow migration question:

> For the prime's frozen migration scope, did every independently expected legacy asset and migrated lifecycle event survive into the normalized target evidence with the agreed invariant fields intact, without silent scope contraction, duplicate identity, or missing retained-interface evidence?

## Base sprint — $28,000 fixed / proposed

### Included scope

- one frozen migration wave;
- up to **100,000 normalized asset-master records**;
- up to **1,000,000 normalized migrated lifecycle-history records**;
- one independent expected source-asset roster;
- one independent expected per-asset migrated-history roster;
- one frozen canonical asset mapping / comparison contract;
- one frozen lifecycle-history comparison contract;
- optional explicit asset-ID preservation rule or source-lineage mapping rule;
- up to **four retained-enterprise interface** acceptance contracts;
- duplicate/conflicting identity checks;
- missing/unexpected asset and history checks;
- required-field and selected invariant-field checks;
- target asset-ID reuse checks;
- complete normalized logical source/target asset and history roots;
- interface roster PASS/evidence gate;
- deterministic SHA-256 integrity receipt when and only when all bounded gates pass;
- exception-first review ledger and one closeout review.

### Delivery window

**15 business days** beginning only after complete authorized intake, frozen normalized acceptance criteria, independent expected rosters, usable evidence sets, and agreed non-production/data-handling conditions.

Incomplete intake moves the start date. It does not silently consume delivery days or weaken the acceptance contract.

### Acceptance criteria

Base sprint is deliverable-complete when:

1. the prime-approved normalized scope and comparison contracts are recorded;
2. expected asset and history rosters are supplied independently of the tested source/target extracts;
3. every admitted asset and migrated history event is deterministically indexed or the blocking input defect is identified;
4. missing/unexpected records, duplicate/conflicting identities, target-ID reuse, required-field loss and selected invariant mismatches are surfaced in bounded evidence;
5. complete normalized source/target asset and history roots are produced;
6. every in-scope retained interface is either `PASS` with a supplied evidence ID or explicitly blocks receipt issuance;
7. a passing bounded scope produces a reproducible contract-bound integrity receipt;
8. same-count different migration evidence, a narrowed scope contract, missing expected records, failed interfaces or receipt tamper cannot masquerade as the same passing evidence;
9. the prime receives the exception ledger, roots, bounded PASS/HOLD result and closeout notes.

A bounded PASS is **not** a conclusion that the target system or program complies with FAR, DFARS, NIST, Section 508, DoD IUID, accounting/audit standards, buyer requirements, or the full IFB.

## Change control

A change is commercially material if it adds a migration domain, increases the record ceiling materially, changes the frozen mapping/rosters, adds an interface, requires production access, changes security/data-handling constraints, or adds a buyer deliverable not listed above.

Material changes pause the affected lane until scope, authority and price are recorded. TJLabs does not absorb an unbounded federal property-management implementation under this fixed-fee acceptance workshare.

## Why a qualified prime should pay for this

Migration programs can appear green when both sides are compared against the same incomplete extract. They can also pass aggregate counts while individual assets are missing, histories are truncated, identifiers are reused, or a retained interface quietly drops from UAT scope.

This workshare sells a narrow independent control against those failure modes. The prime keeps ownership of platform selection, federal-property logic, buyer requirements, cybersecurity, implementation and contractual commitments; TJLabs supplies an exception-first migration continuity and evidence layer with explicit anti-scope-contraction semantics.
