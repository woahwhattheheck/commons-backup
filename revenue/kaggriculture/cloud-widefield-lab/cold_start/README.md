# Retained-input cold scheduling measurement

All 33 fresh SciPy actor calls returned the same complete action under the
existing 1-second RPC deadline. Spacing four starts by 250 ms lowered median
first-call latency but reduced completed first actions per minute by 32.7%.
There is no measured basis here for changing `run_panel.py` or its defaults.

| Concurrent actors | Start spacing | Samples | Median first RPC | Maximum first RPC | Completed first actions/min |
|---|---|---:|---:|---:|---:|
| 1 | simultaneous | 3 | 724.0 ms | 739.6 ms | 70.6 |
| 2 | simultaneous | 6 | 776.5 ms | 813.0 ms | 129.6 |
| 4 | simultaneous | 12 | 898.3 ms | 929.4 ms | 225.6 |
| 4 | 250 ms | 12 | 835.1 ms | 945.6 ms | 151.7 |

These are isolated first-action cohorts, not the original four concurrent
evaluator jobs with candidate and opponent processes. The original three
WIDEFIELD cold failures were not reproduced by this smaller workload. No full
game, engine transition, new game seed, historical-result replacement, or
hosted measurement was performed. Three rounds rotated cohort order; the sample
is too small to establish failure probabilities or a general scheduling rule.

## Reuse

Run from the Commons repository root and choose an unused work/output directory:

```bash
python -B revenue/kaggriculture/cloud-widefield-lab/cold_start/prepare_bank.py --output /tmp/titan-cold-work/bank
python -B revenue/kaggriculture/cloud-widefield-lab/cold_start/prepare_input.py --output /tmp/titan-cold-work/input.json
python -B revenue/kaggriculture/cloud-widefield-lab/cold_start/benchmark.py --bank /tmp/titan-cold-work/bank --input /tmp/titan-cold-work/input.json --output /tmp/titan-cold-work/results.json --repeats 3 --stagger-seconds 0.25
```

The bank is generated by the **existing unchanged builder**. All 22 resulting
original file hashes, including `BANK.json`, the SciPy adapter, the official
loader contract and lonespear source, must match WIDEFIELD's committed freeze.
NumPy 2.3.5 and SciPy 1.17.0 match that freeze; the original bank rejects other
dependency versions. The benchmark does not modify thread environments or
clear host caches. Every sample uses the existing evaluator `Actor`, its
sanitized environment, a fresh interpreter and its normal process cleanup.
OS file pages may already be cached; this is process-cold measurement.

Each sample records process creation through wrapper readiness, the actual
request/response times, first-call CPU/wall costs, errors and final process
resource usage. Readiness is not a separately measured NumPy/SciPy import: the
normal lazy bank/NumPy/SciPy/policy imports occur **inside the first timed call**.
Startup retains its 10-second limit and each action RPC retains its 1-second
limit. Cohort throughput includes intentional spacing and process cleanup;
it is not completed games per minute.

## Input and source identity

The original WIDEFIELD 243-member archive contains compact failed-cell reports,
not the complete 9921017/9921018/9921030 actor inputs. Instead this measurement
uses the unchanged `cloud-opponent-frontier/runtime/fixtures/initial-observation.json`.
`prepare_input.py` checks its exact byte hash and equality with the actual first
observation of `development-v2/sell-lonespear-9881001-seat0.jsonl.gz` in the
retained portfolio archive `f2623819...`.

That observation is the SELL candidate facing lonespear **greedy**, with the
same frozen lonespear policy source as the SciPy target. Configuration was not
retained in the trace and is explicitly supplied from the pinned official
configuration specification, with seed null. There is no retained expected
SciPy action. Identical returned action hash `ce4475f3...` across all cohorts
establishes scheduling-response parity on this workload only. No engine
legality or historical-action correspondence is claimed.

The measured environment is Python 3.12.13, an 8-CPU cgroup quota (9 affinity
CPUs), and a 20-GiB cgroup memory limit. Raw receipts contain full source/input
hashes, actual launch offsets, and every sample; bank/evaluator/driver/input
hashes remained unchanged across the run.

## Preserved evidence and corrected labels

`RESULTS.json` is the original unmodified measurement. Its exact executed
driver is `evidence/benchmark-measured.py.txt`, SHA256
`5a48be3825368085307f4c61b7b372e69c9d25e33b1ee7e8986d65edaab6ded8`.
The later `benchmark.py` improves reporting for future invocations; it was
not used to repeat the 33 samples.

`SUMMARY.json` is derived from those raw samples without actor calls. It fixes
two overly broad original labels: an absent expected action is unknown, and
an action response is a **completed first action**, not an engine-validated
game result. The old raw `matches_expected_action: true` merely meant the
optional check was not requested; it is not evidence of historical equality.
Additional loader-argument/preparation digests in `SUMMARY.json` were read
after timing and are labeled accordingly. The evaluator's loader argument
is unused for this file-based bank target, whose actual contract is separately
covered by the original 22-file freeze.

To regenerate only the corrected summary at a new path:

```bash
python -B revenue/kaggriculture/cloud-widefield-lab/cold_start/benchmark.py --summarize-only revenue/kaggriculture/cloud-widefield-lab/cold_start/RESULTS.json --output /tmp/titan-cold-summary.json
python -B -m unittest discover -s revenue/kaggriculture/cloud-widefield-lab/cold_start -p test_summary.py -v
```

The focused test blocks evaluator loading, bank preparation, cohort execution
and subprocess creation while calling the summary-only CLI. It passes and
verifies all 33 counts, cross-scheduling parity, corrected labels and unchanged
raw bytes. Consumer: WIDEFIELD/T09 can reuse this driver for an explicitly
defined next runtime workload; original games and current scheduling remain
unchanged.
