# UNITRECYCLE — strict later-row no-op recycling

This packet consumes the existing `unit-action-efficacy` census inside the existing
`unit-phase-chaining` authority.  It does not add a controller, route family,
feature key, runtime hook, V4 tree, default, archive, workflow, or Kaggle path.

The authenticated current-native census found 120 later same-target actions that
were strict no-ops only because an earlier actor in the same callback had already
successfully consumed the exact one-shot effect: CARE 48, WATER 44,
COLLECT_FERTILIZER 24, HARVEST 4.  UNITRECYCLE owns the admission question for
those later rows; UNITWASTE retains measurement authority and TILEPIPE retains the
unit-order theorem.

The first admitted subset is intentionally narrower than the census.  A later
`COLLECT_FERTILIZER` or animal `HARVEST` may become `CARE` only when:

- an earlier actor is on the same tile with the exact same source operation;
- pre-callback state proves that earlier operation succeeds (`fertilizer_available`
  for COLLECT, positive animal `yield_units` for HARVEST);
- the tile is a known animal, already fed and not yet cared;
- no earlier CARE or prior UNITRECYCLE replacement owns that tile.

The successful predecessor is never moved or changed.  Therefore its cargo and
all parent market rows stay unchanged.  `CARE` consumes no carried inventory.
Only one replacement per tile is allowed.  Disabled/no-match/malformed cases
return the exact parent action object.

This is a legality/admission carrier, not a strength claim.  The CARE state change
can still be economically useless if later production/feed cadence fails to
realize its pending bonus.  Current-native natural engagement and paired both-seat
economics are mandatory before any runtime wiring.  The remaining CARE/WATER
redundant-row families stay HOLD until their alternate action has independent
inventory/seed/custody proof.
