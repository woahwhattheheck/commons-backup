20 added native-port tests. The original nine-test generic guard suite was not

Executed scope: full exact production helper, exact extracted current runtime
method, native caller-to-helper calls, and the complete unmodified official
interpreter on synthetic fixtures. The rest of TitanAgent, a whole current
production package, and competitive games were NOT executed in this receipt.

changed. The native source port is landed for the ONE current-runtime serializer;
production wiring and opponent-diverse economic validation remain separate gates.

The port changes only fertilizer-prefix reads/rewrites in three helper functions
and the current caller's candidate predicate. It preserves raw slot positions,
ignored suffix content, unit actions, feed-stock source, current liquidity and
water-service checks, and observed-price economic admission. Empty or malformed
raw rows still occupy a slot: cap BEFORE parsing, never filter then cap. The
engine's max(1, int(configured cap)) normalization is used consistently, including
commitment and bonus-water calculations. No new arbitrary-delegate isolation
claim is made for the historical prototype guard.

## Discriminating evidence

The original four predecessor defects reproduce: ignored current HIRE prevents
reservation, ignored BUY_PRODUCT creates a false room conflict, ignored SELL is
rewritten, and ignored future HIRE truncates the useful route. The existing guard
passes those controls; the native source port does too. An added future
BUY_PRODUCT counterexample also rejects the predecessor.

Per mode, the added tests cover 168 current/future suffix cases, 32 below-cap
old/new parity cases, 72 full-interpreter suffix-versus-prefix pairs in both seats,
12 full-interpreter empty-slot cases, and five deliberately reverted native
read/rewrite variants. All five variants are detected. Caps -2, 0, 1, 2, 3 and 10
exercise the literal engine normalization, including cap-zero cash/water safety.

An explicit 48-callback old/native trajectory in each physical seat carries the
unchanged authored PICKUP -> WEST -> FERTILIZE -> due-day WEST/WATER through daily
refresh. With an ignored tail HIRE, the predecessor sells both fertilizer units
and misses the input; native retains one. At refresh the native path has exactly
one additional STRAWBERRY yield unit and $100 LESS current cash. This proves
physical input preservation, NOT final profit, game EV or a win-rate gain.
The engine tests contain 348 interpreter invocations per mode (144 paired-prefix,
12 empty-slot, 192 trajectory calls).

Source-custody tests reject modified/already-transformed helpers, altered or
ambiguous target methods, wrong engines, existing output directories and symlink
aliases. Native runtime transformation binds only the exact stock method, and
retains unrelated runtime text byte-for-byte, allowing peer lifecycle/seed work
to compose without reverting their source. The helper transformation requires
its full exact preimage; reconcile any intervening helper change instead of
weakening that check.

From this directory, with the pinned root helper and checked engine files:

```sh
python -m unittest -v test_operating_stock_current_delegate test_native_stock_prefix
python -O -m unittest -v test_operating_stock_current_delegate test_native_stock_prefix
python -m py_compile port_operating_stock_prefix.py test_native_stock_prefix.py
python -O -m py_compile port_operating_stock_prefix.py test_native_stock_prefix.py
```

The native recipe operates on a verified production source root and writes ONLY
a new, nonexistent directory; it never edits the source root or overwrites an
archive. Inspect its NATIVE-PORT.json and compose the two changed source files
through the sole current-runtime serializer. Do not install the historical
prototype guard as another runtime controller and do not run legacy apply_v4.

```sh
python port_operating_stock_prefix.py \
  --source-root /path/to/cloud-execution-lab \
  --engine /path/to/cloud-execution-lab/checks/reference/engine/kaggriculture.py \
  --output /path/to/new-stock-prefix-output
```

The tests exercise the materialize function directly with a caller fixture;
a full-current-runtime CLI/package run is a remaining composition gate, not a
result asserted by this receipt. Preserve operating_stock=true and all other
existing defaults when consuming this correctness-only source delta.
