# Retained causal history for terminal consumers

`prism_history_inputs.py` extracts the missing full own/public prefix from the
existing PRISM late-milk DEVELOPMENT archive. It calls no engine or policy and
constructs no rival scenario, posterior probability, or action optimization.
This is input delivery for the existing T12 joint-history and terminal-receipt
consumers, not another history predictor or a new game panel.

## Existing source

Library source `prism-late-milk-choice-evidence-20260907.zip`, 7,524,322 bytes,
SHA256 `2f8566ed9cd7cd04d342216c9eb5922f3d8bd361ffd952994439e10e9771907a`.
It retains 16 complete development trajectories, two seeds, both seats, two
opponents, and frozen SELL versus the optional late-recheck arm. This is not
PR9997, the old T05 tie-case collection, or a fresh held set. Source membership,
trace hashes, completion, and the actual archived evaluator are checked before
export. All 72 source manifest members match; the source archive is untouched.

## Runtime payload

Each `runtime/<sha256>.json.gz` expands to one object:

```python
{
    'schema': 'titan.public-own-history.v1',
    'configuration': {...},
    'history': [
        {'observation': own_public_observation_at_t,
         'own_action': recorded_own_action_at_t},  # t = 0 .. 717
    ],
    'observation': own_public_observation_at_718,
    'selected_action': recorded_own_action_at_718,
}
```

The observation contains public farms/market/town/day/hour and THIS actor's
private shed/seeds/carry. The other actor's private observation, authored
current or historical actions, game labels, terminal observation, and rewards
are absent. `index.json` stores source identities and original outcomes for
OFFLINE lookup; it is explicitly not an actor input. Runtime filenames use
payload hashes rather than outcome/opponent/seed labels.

The selected own action is the recorded output of the already-running parent.
It is a valid *selected-action input boundary*, not a claim that an uninitialized
stateful controller could reconstruct it from the terminal observation alone.
For this historical path, each stored history action is the already-observed
own action; do not substitute an action generated by a different controller.

## Clock alignment

The recorder writes an initialization row with `step=-1`, then a POST-action
row with `step=t` after executing decision t. Therefore decision t's input
observation comes from raw row t (recorded step t-1), while its own action is in
raw row t+1 (recorded step t). The archived evaluator explicitly writes the
next decision `step=t` and `remainingOverageTime=0` before every agent call.
This extractor reproduces that normalization, checks day/hour, and omits the
cleared configuration `seed` field. It does not reuse the stale stored step.

At final decision 718, the input is the observation AFTER recorded step717,
and the selected own action is in recorded step718. No data from the final
post-action observation or score enters the runtime payload. The final row's
status is checked offline solely for archive completeness.

## Reuse

From the repository root and an already materialized Library source archive:

```sh
D=revenue/kaggriculture/cloud-score-endgame
python -B "$D/prism_history_inputs.py" \
  --archive /path/to/prism-late-milk-choice-evidence-20260907.zip \
  --output /tmp/prism-public-history-new
python -B -m unittest discover -s "$D" -p 'test_prism_history_inputs.py' -v
for offset in 0 4 8 12; do
  python -B "$D/verify_prism_history_delivery.py" \
    /path/to/prism-late-milk-choice-evidence-20260907.zip \
    /tmp/prism-public-history-new "$offset" 4
done
```

The standard-library verifier defaults to the first four records. Four disjoint
shards cover all 16; offsets index source records, not game seeds. Batching keeps
the executed verification bounded in an interactive cloud harness. Initial
monolithic verifier attempts were interrupted by the tool deadline before a
final result and are not counted as completed validation.

To consume the packet with the existing flow machinery, iterate observations in
chronological order. Infer the prior turn only from adjacent own observations,
the corresponding final own action, and the existing exact post-unit/fill
consumer. A requested sale is NOT automatically a full fill. A missing/censored
fill stays unknown; do not train it as zero. Each prefix contains the five
same-hour prior transitions at 598, 622, 646, 670, and 694 and their following
observations, so the missing earlier-window transport is resolved on THIS bank.

`joint_terminal_history` retains ownership of joining products at the SAME lag
and of the explicit slot/operating-product hypotheses. WHEAT/FERTILIZER gross
buy/sell flows and rival order alignment are not newly identified by this input
packet. The terminal producer still needs the post-unit state from the SAME
selected own action, applied once. No opponent current queue may be supplied
from the offline index or original trace as a runtime scenario.

## Measured delivery

Fourteen boundary methods pass. Four actual-source verification shards cover
11,504 complete observation comparisons and 11,504 own-action comparisons, with
32 excluded-data invariance controls and 80 same-phase prior-transition checks.
Sixteen original source records resolve to 10 distinct complete runtime
payloads; duplicate paths are retained in the source index rather than counted
as independent data. There are two independent development seeds. Public
pre-action scores are ahead in 12 source records and behind in four; there are
no tied-score inputs in this bank.

No historical game, model, or engine transition was rerun. This supplies real
past observations, not evidence that any scenario hypothesis or new policy is
accurate. The original game results retain PRISM's authorship and source pins.
Detailed data stay in the account Library; Git contains only the extractor,
boundary tests, verifier, and this reuse note plus aggregate execution metadata.
