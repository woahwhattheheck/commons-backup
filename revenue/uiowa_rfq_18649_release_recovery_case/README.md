
Choose new output directories; existing directories are never overwritten.
`--ledger path/to/ledger.json` runs an edited synthetic case instead of a named
scenario. `--scenario` and `--ledger` are mutually exclusive. The first command
exports the complete editable ledger, the actual artifact bytes, all four native
inputs and outputs (the environment engine runs at two cutoffs), the complete
source-bound report, the summary, and a SHA-256 manifest. There are 12 files in
the manifest plus the manifest itself. Omit `--output` to print only the summary.

Exit 0 means the offline analysis ran, **not** that recovery was established.
Exit 2 means invalid input, an unavailable/incompatible dependency, or an output
error. Consult the explicit result fields; null is unknown, never zero.

## Input boundaries and retained unknowns

`fixture()` defines the v1 ledger contract in executable form. Required top-level
fields are checked, IDs are unique, timezones are mandatory, JSON duplicate keys
and nonfinite constants are refused, and input is capped at 2 MiB / 500 events.
Unknown supplemental material belongs in `extensions`, which is carried through
unchanged. Supported event kinds are approval, build, artifact, deployment,
environment, detection, attempt and check. This case models one release and one
incident with serial configuration-recovery attempts; it is not a general incident
system, a data-migration recovery model, or an arbitrary component loader.

Missing approval, artifact, build, deployment or detection events remain evidence
gaps rather than being fabricated. Ambiguous singleton events are malformed and
must be distinguished by the supplier. Foreign-release, foreign-artifact and
future records remain in the source register with named exclusion reasons. A
record's presence is not treated as its authenticity.
