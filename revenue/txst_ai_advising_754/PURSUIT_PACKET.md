## 3. Technical delivery spine

These are proposal workstreams to map into the buyer's actual evaluation structure after recovery, not claims that TXST mandated each item.

**Student/advisor interaction.** Define channel boundaries, human-advisor escalation, uncertainty/abstention, transparent source context, and no autonomous academic-policy authority.

**Integration.** Create a versioned interface map across buyer-specified SIS/CRM/LMS/identity/advising services; define idempotency, retry/reconciliation, contract tests, cutover, and rollback.

**AI-governance acceptance.** Bind model/prompt/policy versions to evaluated behavior; preserve provenance; measure hallucination/unsupported-claim rates, calibration, fairness/subgroup behavior where buyer-approved data allows, and human-override outcomes.

**Privacy/security.** Minimize student data; separate production access from synthetic/deidentified evaluation; preserve least-data test fixtures; bind logs/evidence without turning the carrier into a compliance certification.

**Accessibility.** Build buyer-standard-specific acceptance after the exact standard/version is known, including keyboard, screen-reader, focus, contrast, language, error-state, and multimodal interaction testing as applicable.

**Implementation and adoption.** Phase discovery, interface proof, pilot, migration/cutover, advisor training, student rollout, support/handoff, and change control. Each phase ends in buyer-reviewable acceptance evidence rather than a progress-only narrative.
