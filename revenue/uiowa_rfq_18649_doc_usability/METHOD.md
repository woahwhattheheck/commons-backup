# UIOWA-048 review method

This kit reviews architectural overviews, decision records, onboarding guides, and operating documentation by testing whether another practitioner can find and use the material for a bounded task. The examples are fictional.

## Method

1. Inventory the small set of artifacts practitioners actually rely on. Record the source reference, whether it was located, a maintainer role when known, and a review date when available.
2. Keep four questions separate: discoverability, maintenance responsibility, review recency, and task usability.
3. Choose one representative task that the artifact is supposed to support.
4. Observe a practitioner using the artifact when possible. Record searches, assumptions, dead ends, and assistance.
5. Preserve the evidence type: observed walkthrough, artifact review, interview report, or not observed.
6. Turn gaps into proportionate improvements rather than document-volume targets.

A recent review date is not proof of correctness. An available artifact is not proof of usability. A document that was not located is a documentation gap; it does not prove the underlying practice is absent.

## Practical improvement options

Prefer changes a mid-size IT team can sustain:

- assign a maintainer role instead of relying on one named person;
- review after meaningful events such as a release, architecture change, support handoff, or staff transition;
- write the minimum task-oriented aid needed for a real workflow;
- mark replaced decision records clearly;
- validate updates by repeating the bounded task;
- archive or label obsolete material instead of leaving conflicting versions equally discoverable.

## Worksheet interpretation

The documentation inventory captures stable document ID, group, document kind, title, source reference, located state, maintainer role, last-reviewed date, and notes.

The task worksheet captures task ID, group, task name, criticality, expected document kinds, linked document IDs, evidence type, observation date, result, and notes.

Report observations in evidence terms. Examples: a sampled task was completed using a recent overview; a decision note is old and has no recorded maintainer role; an expected guide was not located. Do not convert those observations into claims about all services or department-wide maturity without broader evidence.
