## Qualification decision tree

### PRIME

Choose **PRIME** only when all of the following are verified:

- mandatory firm experience is satisfied by real, supportable evidence;
- required references exist, are permissioned where needed, and are contactable;
- named staff meet required qualifications and are actually available;
- required insurance can be evidenced at the required limits;
- legal/entity/Colorado registration obligations can be satisfied on the buyer's timetable;
- no mandatory meeting, registration, addendum, or question-stage requirement has been missed;
- the requested ERP scope matches capabilities we can actually deliver;
- commercial and signature authority exists for the response.

### TEAM / SUBCONSULT

Choose **TEAM** when the technical work is a fit but one or more prime-level gates are unsupported, especially long-tenure municipal ERP references, insurance, firm history, or named-staff depth.

The teaming offer should be bounded and paid. The primary value is a specialist execution package that a qualified ERP advisory / implementation prime can insert into its response and later delivery plan without handing over undefined free labor.

### NO-BID

Choose **NO-BID** when authoritative terms create a non-curable gate, such as a mandatory event already missed, qualification/licensure requirements neither TJLabs nor a feasible prime relationship can satisfy, unacceptable contractual exposure, or a scope materially outside the team's delivery capability.

No-bid should be a recorded decision, not silent abandonment.

## Paid specialist workshare thesis

Do **not** present TJLabs as a generic ERP implementation house unless evidence supports that claim. A more defensible workshare is to own bounded, technically demanding seams around the ERP program.

### Workstream A — current-state data and workflow evidence

Deliverables:

- system / data-source inventory with ownership and interface map;
- workflow evidence map for selected finance, HR, procurement, reporting, or adjacent processes named by the prime/buyer;
- integration/API/file-exchange inventory;
- control and reconciliation touchpoint map;
- issue / ambiguity register with source evidence.

Acceptance: every mapped interface/workflow carries a source, owner, and unresolved-state marker; unknowns remain explicit rather than inferred.

### Workstream B — integration and migration validation

Deliverables:

- source-to-target field / transformation checks;
- deterministic reconciliation rules;
- duplicate, null, referential-integrity, and balance checks;
- migration rehearsal result packs;
- exception triage output suitable for buyer/prime review.

Acceptance: validation runs are reproducible against identical inputs; exceptions are enumerated and traceable to source records / rules.

### Workstream C — automated test and acceptance harnesses

Deliverables:

- API/integration smoke tests;
- workflow acceptance fixtures;
- reconciliation assertions;
- regression checks for critical interfaces/reports;
- evidence-bound test receipts that distinguish pass, fail, and untested states.

Acceptance: no false-green from missing evidence; test outputs contain exact input/version identity and deterministic result state.

### Workstream D — reporting / control diagnostics

Deliverables:

- reporting gap and data-quality diagnostics;
- control failure / manual-reconciliation inventory;
- candidate automation backlog ranked by evidence-supported operational impact;
- bounded proof-of-value automation for a selected high-friction workflow when approved.

Acceptance: recommendations separate measured evidence from assumptions and do not claim savings before a baseline is established.

### Workstream E — operational automation prototyping

Potential seams, only if present in the authoritative scope:

- evidence-backed AP / invoice exception triage;
- reconciliation support;
- workflow routing and escalation;
- structured document extraction with human review;
- integration monitoring;
- data-quality alerts;
- repeatable test-data / migration-data preparation.

This workstream is optional and cannot be represented as part of buyer scope until the solicitation confirms it.

## Delivery shape for a prime/team response

A credible specialist insertion can be framed as four stages:

1. **Evidence discovery** — lock sources, interfaces, owners, control points, and unknowns.
2. **Validation architecture** — define deterministic checks, acceptance states, and traceability.
3. **Execution / proof** — run bounded integration, migration, reporting, or automation work against approved data and environments.
4. **Handoff / operationalization** — deliver runbooks, evidence receipts, exception queues, and knowledge transfer.

This makes the work measurable and lets a prime price the TJLabs seam separately from its own ERP advisory, PMO, configuration, and organizational-change work.
