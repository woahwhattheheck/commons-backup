# Requirement and evidence matrix

This is an internal preparation surface.

| Topic | Evidence available now | Remaining gate |
| --- | --- | --- |
| Existing reporting estate | Migration inventory and parity method | Reconcile exact current source package |
| Traditional reports | Exact typed old-versus-new comparison method | Approved fixtures and presentation rules |
| Interactive analysis | Semantic-lineage and governed-definition approach | Final platform selection |
| Dashboards | Architecture boundaries and acceptance method | Final presentation platform |
| Oracle coexistence | Reporting-layer boundary and source-lineage model | Approved interfaces and connectivity |
| Legacy document migration | Inventory, dependency, parity, and retirement controls | Actual catalog and usage evidence |
| Safeguards | Least-privilege architecture and access-class model | Customer control requirements |
| Microsoft GCC | Dependency checklist and boundary questions | Actual selected services and tenant architecture |
| Implementation | Discovery, pilot, migration waves, validation, transition | Customer schedule and environments |
| Relevant experience | No unsupported claim | Real company/project evidence |
| References | No unsupported claim | Authorized customer references |
| Cost discussion | Cost-driver structure can be prepared | Owner-approved commercial inputs |
| Submission mechanics | Procurement guidance retained | Verify current package and addenda |

## Evidence classes

- **DEMONSTRATED_METHOD** — supported by code, fixtures, or repeatable tests in this carrier.
- **ARCHITECTURE_POSITION** — a proposed method that does not imply a deployed customer implementation.
- **BUYER_FACT** — retained from the controlling source generation.
- **COMPANY_EVIDENCE_REQUIRED** — legal-entity, project, reference, personnel, certification, or commercial evidence that must come from a real source.

A missing company fact remains missing. Drafting does not promote it into evidence.
