# UIOWA-051 — A requirement changes; what happens to the design evidence?

**Synthetic operator readout.** This is an executed example using CINDER's
secure-design instrument with MERIDIAN-H6K9's retained interchange repair.
It is not a University of Iowa finding, a security assessment or a compliance verdict.

## The decision to inspect

The fictional build pipeline promotes an artifact and records its originating
build identifier. Decision `DD-SYN-02` cites requirement `SEC-REQ-SYN-02` v1;
record `EV-SD-SYN-06` states that the identifier is carried with the artifact.
The tool classifies this supplied record as `OBSERVED_PRACTICE`. It does not
open the artifact or prove that a live pipeline does what the record says.

## Three actual engine snapshots

| Snapshot | Requirement | Current evidence | Stale evidence | Link state |
|---|---:|---|---|---|
| Baseline | v1 | `EV-SD-SYN-06` | None | `OBSERVED_PRACTICE` |
| Requirement changed | v2 | None | `EV-SD-SYN-06` | `TRACED_STALE` |
| Decision revisited | v2 | `EV-REHEARSAL-1` | `EV-SD-SYN-06` | `OBSERVED_PRACTICE` |

The rehearsal adds a fictional obligation to retain a decision-specific review
reference. It changes the requirement text and increments its version; it does
not rewrite `EV-SD-SYN-06` to pretend that an old artifact considered new text.
That unchanged artifact is now stale. The next operator action is to ask which
design decision was revisited and obtain the corresponding current-version record.

Only after a new fictional design-review record explicitly names this decision,
requirement and current version does the selected link return to observed
practice. The old artifact stays in the stale-evidence list. Historical provenance
is not erased merely because newer evidence exists.

The unrelated `DD-SYN-01` / `SEC-REQ-SYN-01` stale link and `DD-SYN-05` unknown
link remain unchanged in all three snapshots. Improving one link does not
sweep the rest of the worksheet into a passing state. Each snapshot is serialized
to JSON and loaded through the real model again; the entire reassessed object,
not just the summary count, is compared for equality.

## Run and inspect it

From the component directory in an existing cloud checkout:

```bash
python rehearse_change.py
python rehearse_change.py --out-dir NEW_REHEARSAL_DIRECTORY
```

Expected readable output from the executed fixture:

```text
SYNTHETIC SECURE-DESIGN CHANGE REHEARSAL
DD-SYN-02 <- SEC-REQ-SYN-02
baseline: v1 OBSERVED_PRACTICE; current=1, stale=0; JSON round-trip identical

decision_revisited: v2 OBSERVED_PRACTICE; current=1, stale=1; JSON round-trip identical
Fictional evidence only. Artifact content and actual controls were not verified.
```

The new directory contains 14 files: the readable summary, three JSON
assessments, three CSV matrices, three worksheets, three evidence chains, and a
manifest. Open `requirement_changed-chain.md` for the stale artifact and next
question; open `decision_revisited.json` to see both old and new evidence. JSON is
the canonical source-carrying export, while CSV and Markdown are review views.

The source fixture is unchanged. Existing output paths are refused. A fresh
directory can still be incomplete after an I/O failure; a manifest written last
is not an atomic installation. Require exit zero, all 13 manifest entries,
matching lengths and hashes, and the three expected states before handing over
this synthetic bundle. The manifest proves generated byte identity, not artifact
quality, provenance outside these supplied records, or authorizing execution.

## Review actions exposed by the repair

**Lost evidence on reopen.** The predecessor's assessment export lacked the
source evidence collection. Re-importing the otherwise valid six-link export
produced six unknown links. The repaired export retains all source evidence;
missing optional IDs stay absent rather than becoming a literal `None` string.
Older exports must be regenerated from their source records, not reconstructed
by believing a derived state.

**Wrong flow.** An artifact explicitly naming another flow cannot establish
practice for this decision. It remains visible as a mismatch to reconcile. A
separate valid current record is still counted, with the contradiction visible
and a next-step request; contradictory evidence is not quietly discarded.

**Unknown is not false.** An omitted or null trust-boundary field remains unknown.
An explicit false remains false. A string such as `"false"` is refused instead of
being interpreted as a truthy crossing. Missing source records and malformed
record structures are different situations; malformed inputs receive named errors.

## What this demonstration does not establish

The existence of a real versioned requirement register, the completeness of real
data-flow inventories, the quality of any design review, actual control operation,
and any university-specific conclusion all remain uncollected. The four-state
classification organizes supplied evidence; it is not a maturity score or an audit.
[NIST SSDF / SP 800-218](https://csrc.nist.gov/Projects/ssdf) remains a reference
frame only. No network, credential, deployment, price, external contact or scheduling
action is part of the rehearsal.
